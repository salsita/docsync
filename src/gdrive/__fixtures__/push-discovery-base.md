# About this document

This document compiles a list of inputs Salsita will need in order to perform Discovery for the configurator project and deliver it in a timely manner. We require those inputs in order to form a clear picture of the product and its constraints. We’ll study them offline in preparation for the first Discovery call.

We don’t require any specific format for this information, because we understand each client will have most of that information already, in various formats, and it’s much easier for everyone to provide what already exists. If you already have the requested information available, feel free to provide it directly as is. There’s no need to do additional work to, for example, make sure you have a separate document for each of the bullet points we describe: as long as the documents contain the information, we’re able to clearly understand the content, what’s actually in scope for this phase, and it’s up to date regarding the configurator project, it’s enough.

This document serves as an initial overview for our clients to get an idea of what will be required, and be able to start preparing the materials ahead of time. It’s not meant to be fully exhaustive, nor act as a checklist: more inputs will often be needed as our understanding of the configurable products and other project parameters evolve.

Any questions can be clarified by email or can be discussed live during the Kickoff meeting.

## Before Discovery starts (between contract signature and at latest 1 week after Kickoff)

**Product information**

For each SKU that will be configurable:

- Name
- Short description
- Visual reference

Product catalogues: up to date with what will be configured, and in the greatest level of detail available

**Rules**

Complete list of product rules:

- Compatibilities between product options
- Minimum/maximum dimensions
- Structural rules (i.e. an additional support is required for every 1500mm)
- Any other relevant rules or constraints

**Formulas**

Any relevant formulas that the configurator will need to implement

- Pricing
- Calculating dimensions
- Weight
- Shipping
- …

If they already exist in some form (spreadsheet, code, etc.), it’s easier for both sides if you provide that.

**Output examples**

Ideally, one or two examples of already existing outputs the configurator will generate, for configurations that we expect the configurator will typically create. If not possible, provide something as close as you have. This is for us to understand the expected content and get inspired on the format and layout:

- PDF(s)
- Email
- BOM
- CAD files

## Before Discovery ends (4 weeks after Kickoff)

- 3D assets for all parts that will be visualized in the configurator
  - 3D models
  - Textures
  - Visual references: Real photographs when possible\
    &#x20;

- Branding:
  - A source from which we can infer the branding to use in the configurator
    - Could be your homepage, an existing configurator, a design guide, or any other source that lets us capture information about desired colors, fonts, and visual style.\\

- Integration:
  - Very project-dependant: Access, endpoints, payload formats
